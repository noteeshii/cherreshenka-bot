# Cherreshenka — Twitch-бот и оверлей

Бот на TypeScript, который получает события Twitch через WebSocket Streamer.bot, воспроизводит заказы музыки и синхронизирует стикеры чата с OBS. В проект также входят уведомления DonationAlerts, игровые команды и интеграция с API аукциона.

## Возможности

- Общая очередь заказов YouTube и Яндекс Музыки за баллы канала, локальное воспроизведение через mpv.
- Пауза, продолжение, пропуск, громкость, просмотр и отмена заказов; лайки и дизлайки Яндекс Музыки.
- Оверлей на Vue 3 и Pinia: сообщения-стикеры, эмоуты Twitch/7TV, темы, профили, безопасные области, перемещение, закрепление и удаление стикеров.
- Обычный режим оверлея и режим наград за баллы канала.
- Анонсы донатов DonationAlerts в Twitch.
- Стрельба со статистикой, розыгрыш сладостей и отправка лотов в аукцион.

## Требования

- **Node.js 22.18+** с поддержкой запуска TypeScript без отдельной сборки и npm. Для сборки оверлея рекомендуется актуальная LTS-версия Node.js, совместимая с Vite 8.
- Streamer.bot с подключёнными Twitch Broadcaster Account и Bot Account.
- Актуальные **mpv** и **yt-dlp**, доступные в `PATH` либо по путям из настроек.
- OAuth-токен DonationAlerts: текущая точка входа создаёт эту интеграцию безусловно; без токена запуск завершается ошибкой.

На macOS зависимости для музыки можно установить через Homebrew:

```sh
brew install mpv yt-dlp
```

Для других ОС используйте инструкции [mpv](https://mpv.io/installation/) и [yt-dlp](https://github.com/yt-dlp/yt-dlp#installation). При запуске бот проверяет обе программы. yt-dlp использует Node.js для JavaScript-проверок YouTube.

## Установка и запуск

```sh
npm ci
```

Создайте в корне проекта файл `.env` вручную:

```dotenv
STREAMERBOT_URL=ws://127.0.0.1:8080/
STREAMERBOT_PASSWORD=your-websocket-password
OVERLAY_URL=ws://127.0.0.1:17891

TWITCH_CHANNEL_NAME=your-channel-login
TWITCH_BOT_LOGIN=your-bot-login
TWITCH_CHANNEL_ID=your-channel-id
TWITCH_ACCESS_TOKEN=your-twitch-access-token
TWITCH_CLIENT_ID=your-twitch-client-id

DONATION_ALERTS_ACCESS_TOKEN=your-donationalerts-oauth-token

REWARDS_MUSIC_ID=your-music-reward-id
REWARDS_BASIC_STICKER_ID=your-basic-sticker-reward-id
REWARDS_PINNED_STICKER_ID=your-pinned-sticker-reward-id

MPV_PATH=mpv
YT_DLP_PATH=yt-dlp
YANDEX_MUSIC_TOKEN=
LOG_LEVEL=all
HIT_CHANCE=6

AUCTION_BASE_PATH=
AUCTION_ACCESS_TOKEN=
```

Замените значения на свои; логины указывайте без `@` и `#`. `.env` исключён из Git. Не публикуйте токены и пароли.

```sh
npm start
```

Для перезапуска при изменении исходников:

```sh
npm run dev
```

Запускайте команды из корня проекта. Скрипты автоматически читают `.env`; после изменения настроек перезапустите бот. `Ctrl+C`, `SIGTERM` и `SIGHUP` закрывают соединения, останавливают музыку и сохраняют постоянное хранилище.

### Настройки окружения

Источник актуальных имён — `extensions/config.ts`.

| Переменная                                                     | Назначение                                                                           |
| -------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| `STREAMERBOT_URL`                                              | Адрес WebSocket Streamer.bot; указывайте порт явно                                   |
| `STREAMERBOT_PASSWORD`                                         | Пароль WebSocket Authentication                                                      |
| `OVERLAY_URL`                                                  | Host и порт локального WebSocket-сервера оверлея; используйте `ws://127.0.0.1:17891` |
| `TWITCH_CHANNEL_NAME`, `TWITCH_BOT_LOGIN`                      | Логины стримера и бота; проверяются после подключения                                |
| `TWITCH_CHANNEL_ID`, `TWITCH_ACCESS_TOKEN`, `TWITCH_CLIENT_ID` | Данные для прямых запросов Twitch API                                                |
| `DONATION_ALERTS_ACCESS_TOKEN`                                 | OAuth-токен для получения донатов; обязателен при текущем запуске                    |
| `REWARDS_MUSIC_ID`                                             | ID награды заказа музыки                                                             |
| `REWARDS_BASIC_STICKER_ID`, `REWARDS_PINNED_STICKER_ID`        | ID обычной и закрепляемой стикерных наград                                           |
| `MPV_PATH`, `YT_DLP_PATH`                                      | Исполняемые файлы; по умолчанию `mpv` и `yt-dlp`                                     |
| `YANDEX_MUSIC_TOKEN`                                           | OAuth-токен аккаунта Яндекс Музыки                                                   |
| `AUCTION_BASE_PATH`, `AUCTION_ACCESS_TOKEN`                    | Базовый URL и Bearer-токен API аукциона для `UseSweet`                               |
| `HIT_CHANCE`                                                   | Параметр вероятности попадания игровой команды; по умолчанию `6`                     |
| `LOG_LEVEL`                                                    | `all` по умолчанию либо только один уровень: `debug`, `info`, `warn`, `error`        |

`LOG_LEVEL` — не порог: значение `info`, например, не включает ошибки. Для диагностики используйте `all`.

Старые имена `TWITCH_CHANNEL` и `MUSIC_REWARD_ID`, а также `DEBUG_CHAT` и `TWITCH_USE_BOT` текущая конфигурация не читает.

## Настройка Streamer.bot

1. Подключите Twitch Broadcaster Account и **Bot Account**. Обычные ответы отправляются от Bot Account; одного значения `TWITCH_BOT_LOGIN` недостаточно для авторизации.
2. В **Servers / Clients → WebSocket Server** включите сервер и **Authentication**. Укажите одинаковый пароль здесь и в `.env`.
3. Создайте награду заказа музыки с обязательным текстовым вводом. Скопируйте её ID в `REWARDS_MUSIC_ID`.
4. При необходимости создайте две стикерные награды и укажите их ID в соответствующих `REWARDS_*`.
5. Настройте команды Streamer.bot: бот обрабатывает событие **`Command.Triggered`**, сопоставляя его поле `name` с именем действия из таблицы ниже.

**Бот не разбирает `!песня` и другие текстовые алиасы самостоятельно.** Алиасы и ограничения доступа задаются в Streamer.bot. Имена команд должны совпадать точно, включая регистр. Например, чат-алиас `!песня` должен запускать команду с именем `SendCurrentTrack`.

### Команды

| Имя команды в Streamer.bot | Пример чат-алиаса   | Назначение                                        |
| -------------------------- | ------------------- | ------------------------------------------------- |
| `SendCurrentTrack`         | `!песня`            | Текущий трек                                      |
| `SendTracksQueue`          | `!треки`          | Первые 10 ожидающих заказов                       |
| `SendTracksQueueSize`      | `!очередь`    | Число ожидающих треков                            |
| `PauseCurrentTrack`        | `!пауза`            | Пауза                                             |
| `ResumeCurrentTrack`       | `!продолжить`       | Продолжить воспроизведение                        |
| `SkipCurrentTrack`         | `!пропустить`       | Пропустить текущий трек                           |
| `SetTracksVolume`          | `!громкость 50`     | Громкость: целое число от 1 до 100                |
| `RemoveTrackFromQueue`     | `!отмена 2`    | Удалить ожидающий заказ по позиции, начиная с 1   |
| `LikeCurrentTrack`         | `!лайк`             | Лайк текущего трека Яндекс Музыки                 |
| `DislikeCurrentTrack`      | `!дизлайк`          | «Не рекомендовать» текущий трек Яндекс Музыки     |
| `ShootUser`                | `!выстрел <username>` | Выстрел в пользователя; без цели — в себя         |
| `SendShootsStat`           | `!стата`         | Личная статистика                                 |
| `SendShootLeaders`         | `!топвыстрелов`     | Пять лидеров по попаданиям                        |
| `TrickOrTreat`             | `!сладостьилигадость`         | Розыгрыш сладости и игровых исходов               |
| `UseSweet`                 | `!сладость <название>`     | Потратить сладость на лот аукциона стоимостью 500 |

Примеры алиасов — рекомендации, а не встроенные настройки. Аргумент команды передаётся в поле `message` события.

Удалять чужой заказ может модератор или владелец канала; свой — сам заказчик. **Для остальных команд таблицы проверки прав в коде нет**: ограничьте управление музыкой и изменение музыкальных предпочтений в Streamer.bot. Лайки и дизлайки изменяют аккаунт, чей `YANDEX_MUSIC_TOKEN` указан в `.env`.

### Действия Streamer.bot

Часть функций вызывает отдельные Actions по точным именам:

| Action                                                      | Аргументы                            | Для чего                              |
| ----------------------------------------------------------- | ------------------------------------ | ------------------------------------- |
| `SendAnnounce`                                              | `message`                            | Анонсы, в том числе донатов           |
| `TimeoutUser`                                               | `userName`, `duration`               | Таймаут пользователя                  |
| `UpdateRedemptionStatus`                                    | `rewardId`, `redemptionId`, `status` | Отмена или подтверждение награды      |
| `UserHitYourself`, `UserMissYourself`                       | `user`                               | Исход выстрела в себя                 |
| `UserHitModerator`, `UserHitOtherUser`, `UserMissOtherUser` | `user`, `targetUser`                 | Исход выстрела в другого пользователя |
| `SweetRolled`, `DeathRolled`, `PoopRolled`                  | `user`                               | Исход `TrickOrTreat`                  |

Для `UpdateRedemptionStatus` добавьте поддействие **Execute C# Code** с содержимым `streamerbot/UpdateRedemptionStatus.cs`. Остальные действия нужно настроить в Streamer.bot самостоятельно.

## Музыка

Звук воспроизводится **на компьютере с Node.js**, через локальный mpv. Добавьте соответствующий аудиовыход или звук приложения в OBS: WebSocket не передаёт звук на другой компьютер.

### Источники

- **YouTube:** ссылки на отдельное видео, в том числе `youtu.be`, `/watch`, `/shorts`, `/embed` и `/live`. Плейлисты, активные и предстоящие трансляции не поддерживаются. Метаданные и аудиоссылки получает yt-dlp.
- **Яндекс Музыка:** ссылки на трек `/track/ID` или `/album/ID/track/ID` на доменах `music.yandex.ru`, `.com`, `.kz`, `.by`, `.ua`. Ссылки на альбомы, плейлисты и короткие ссылки не подходят. Используется отдельный клиент API, а не yt-dlp.

Для Яндекс Музыки задайте `YANDEX_MUSIC_TOKEN` — OAuth-токен аккаунта с доступом к треку. Это не пароль и не токен Twitch. Инструкции сообщества: [получение токена](https://ym.marshal.dev/token/). Интеграция опирается на API, описанный [клиентом сообщества](https://github.com/MarshalX/yandex-music-api), а не на публично документированный Яндексом контракт.

Бот требует полный MP3-поток и не подменяет его предпросмотром. При проблемах проверьте токен, подписку и регион аккаунта.

### Очередь и возврат баллов

- YouTube и Яндекс Музыка используют одну последовательную очередь; максимум — 100 ожидающих заказов без текущего трека.
- Свежая аудиоссылка запрашивается перед воспроизведением. Ошибка получения аудио или плеера записывается в лог; очередь переходит дальше.
- Очередь хранится в памяти и не восстанавливается после перезапуска. Пропущенные при отключении WebSocket события не воспроизводятся повторно.
- Ошибка добавления и явное удаление ожидающего заказа вызывают отмену награды (`CANCELED`) через `UpdateRedemptionStatus`.
- Автоматического подтверждения награды после воспроизведения, возврата при пропуске или ошибке проигрывания нет.

### Диагностика

```sh
npm run diagnose:music -- "https://music.yandex.ru/album/7251786/track/44252390"
```

Скрипт читает `.env`, проверяет источник, но не запускает плеер и не скачивает аудиофайл. Для Яндекса проверяет метаданные и получение полного аудиопотока без вывода токена и аудиоссылки; для YouTube выводит диагностику yt-dlp. Передавайте обычный URL без Markdown-разметки.

## Стикерный оверлей для OBS

Оверлей — отдельное веб-приложение. Его WebSocket-сервер запускается вместе с ботом, а HTML собирается отдельно.

### Разработка

В другом терминале:

```sh
npm run dev:overlay
```

Откройте адрес, который напечатает Vite. Выберите профиль, задайте канал, тему, время жизни и безопасные области. Используйте демонстрационные стикеры для проверки оформления. Скопируйте сгенерированную ссылку оверлея в Browser Source OBS.

### Сборка

```sh
npm run build:overlay
```

Результат — `overlay.dist/index.html`: сборка использует `vite-plugin-singlefile`. Для проверки собранной версии:

```sh
npm run preview:overlay
```

Используйте адрес preview-сервера для панели и сгенерированной ссылки OBS. Сервер Vite/preview и бот — разные процессы; запуск одного не запускает другой.

### Особенности

- Фронтенд подключается к **фиксированному `ws://127.0.0.1:17891`**. `OVERLAY_URL` меняет только адрес сервера в Node.js, но не адрес в браузере. Для работы без изменений кода запускайте бот и OBS на одном компьютере с указанным портом.
- Синхронизация оверлея не имеет аутентификации и TLS. Не выставляйте её порт в интернет; оставляйте host `127.0.0.1`.
- Сообщения приходят через Streamer.bot, прямого подключения браузера к Twitch нет. Канал профиля должен соответствовать каналу событий.
- В обычном режиме показываются обычные сообщения; в режиме наград — сообщения с признаком стикерной награды. Награда добавляет пользователю временный счётчик, который расходуется при обработке следующего сообщения: сначала закреплённый, затем обычный стикер.
- Закрепляемый наградной стикер живёт 10 минут; следующий такой стикер заменяет предыдущий. Удаление сообщения в Twitch убирает связанный стикер.
- Поддерживаются эмоуты Twitch и 7TV из событий Streamer.bot; zero-width эмоуты пропускаются. Текст на стикере ограничен 220 кодовыми точками.
- Настройки профилей сохраняются браузером в `localStorage`; серверные профили и доски стикеров находятся в памяти, не в `storage.json`.

## Хранение данных

`extensions/storage.ts` разделяет временные и постоянные данные пользователей и общие переменные. Постоянные данные записываются в `storage.json` в корне проекта при изменениях с интервалом 5 секунд и при штатной остановке. Временные данные сбрасываются при перезапуске.

`storage.json` исключён из Git. Сделайте резервную копию, если важна накопленная игровая статистика. Музыкальная очередь и серверное состояние оверлея этим хранилищем не сохраняются.

## Если что-то не работает

1. **Ошибка при запуске:** проверьте оба URL с явными портами, наличие mpv/yt-dlp и токена DonationAlerts. Частичный набор настроек не отключает интеграции автоматически.
2. **WebSocket подключён, но чат молчит:** проверьте Authentication и пароль, авторизацию обоих Twitch-аккаунтов и совпадение `TWITCH_CHANNEL_NAME`/`TWITCH_BOT_LOGIN`. Сообщение о подключении ещё не гарантирует отправку в чат.
3. **Команда не выполняется:** проверьте получение `Command.Triggered`, точное имя команды и её настройки в Streamer.bot. Одного события `Twitch.ChatMessage` недостаточно для запуска музыкальной команды.
4. **Не возвращаются баллы:** проверьте действие `UpdateRedemptionStatus` и C#-подпрограмму. Пропуск текущего трека и ошибка воспроизведения сами по себе возврат не вызывают.
5. **В оверлее нет сообщений:** проверьте запущенный бот, свободный порт `17891`, канал профиля и выбранный режим наград. Статус канала в интерфейсе не является проверкой реального соединения Twitch.
6. **Музыка не слышна зрителям:** проверьте локальный звук mpv и захват аудио в OBS. Для источника отдельно запустите `diagnose:music`.

Перед эфиром проверьте два заказа подряд, паузу, продолжение, пропуск, возврат отменённого заказа, стикеры и звук в OBS.

Полезные ссылки: [Streamer.bot WebSocket API](https://docs.streamer.bot/api/websocket/requests), [mpv JSON IPC](https://mpv.io/manual/stable/#json-ipc), [yt-dlp](https://github.com/yt-dlp/yt-dlp).
