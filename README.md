# Cherreshenka — Twitch-бот

Музыкальная очередь по наградам за баллы канала. Бот получает события streamer.bot через WebSocket, извлекает аудиопоток YouTube через yt-dlp и воспроизводит его через mpv на компьютере с Node.js.

## Подготовка

Нужны Node.js 22.18+, актуальные **yt-dlp** и **mpv**, доступные в PATH. Для macOS с Homebrew:

```sh
brew install mpv yt-dlp
```

Для Windows или Linux установите программы по инструкциям [mpv](https://mpv.io/installation/) и [yt-dlp](https://github.com/yt-dlp/yt-dlp#installation). Если программы не находятся через PATH, задайте пути к исполняемым файлам в `MPV_PATH` и `YT_DLP_PATH`. При запуске бот проверяет обе зависимости. yt-dlp использует установленный Node.js для JavaScript-проверок YouTube.

1. В streamer.bot подключите Twitch Broadcaster и **Bot Account**. Ответы музыкального бота отправляются именно от Bot Account.
2. В **Servers / Clients → WebSocket Server** включите сервер и задайте пароль.
3. Создайте награду «Заказать музыку» с обязательным вводом текста. Пользователь должен указать ссылку на одно видео YouTube. Укажите ID этой награды в `MUSIC_REWARD_ID`.
4. Подготовьте окружение:

```sh
npm ci
cp .env.example .env
```

Заполните `.env`:

```dotenv
STREAMERBOT_URL=ws://127.0.0.1:8080/
STREAMERBOT_PASSWORD=ваш-пароль
TWITCH_BOT_LOGIN=логин-бота
TWITCH_CHANNEL=логин-канала
MUSIC_REWARD_ID=id-награды
MPV_PATH=mpv
YT_DLP_PATH=yt-dlp
```

Логины указываются без `@` и `#`. Если streamer.bot работает на другом компьютере, используйте его адрес. Без `MUSIC_REWARD_ID` заказы не обрабатываются. После изменения `.env` перезапустите бот.

```sh
npm run check
npm start
```

Для разработки — `npm run dev`. Ctrl+C / SIGTERM останавливает плеер, очищает очередь и закрывает WebSocket.

## Команды

| Команда            | Доступ              | Действие                                               |
| ------------------ | ------------------- | ------------------------------------------------------ |
| `!песня`           | Все                 | Название текущего трека; на паузе название сохраняется |
| `!очередь`         | Все                 | Список ожидающих треков по порядку                     |
| `!пауза`           | Модератор / стример | Приостановить воспроизведение                          |
| `!продолжить`      | Модератор / стример | Продолжить воспроизведение                             |
| `!громкость 1-100` | Модератор / стример | Установить громкость плеера                            |
| `!пропустить`      | Модератор / стример | Пропустить текущий трек и перейти к следующему         |

Старые команды удалены. Права определяются по badges события Twitch. `!песня` ограничена одним вызовом на пользователя за 3 секунды. Команды управления выполняются без cooldown, чтобы можно было сразу продолжить после паузы. Повторные события, сообщения бота, внутренние и тестовые сообщения игнорируются.

Громкость по умолчанию — 50%. Новое значение применяется к текущему и следующим трекам, в том числе если команда вызвана при пустой очереди. После перезапуска громкость снова равна 50%.

## Звук и очередь

Звук воспроизводится **на компьютере с ботом**, через стандартный аудиовыход mpv. Чтобы зрители слышали музыку, добавьте соответствующий выход или звук приложения в OBS. WebSocket не передаёт звук на компьютер со streamer.bot.

Заказы сохраняют порядок поступления. Аудиоссылка извлекается перед воспроизведением, чтобы не устаревать при ожидании. Название становится доступно после получения метаданных, перед запуском плеера. В очередь помещается до 100 ожидающих видео. Ссылки `youtu.be`, `/watch`, `/shorts`, `/embed` и `/live` нормализуются до одного видео; плейлисты и активные трансляции не принимаются.

Ошибочную ссылку бот объясняет в чате. Ошибки получения аудио и воспроизведения выводятся в консоль; очередь переходит дальше. Баллы автоматически не возвращаются, покупки наград не подтверждаются. Очередь хранится в памяти и не восстанавливается после перезапуска. Пропущенные во время отключения WebSocket события также не восстанавливаются.

Для музыкальных функций `Dispatch.cs` не нужен. Он сохранён вместе с API анонсов и таймаутов для использования из кода; музыкальные команды его не вызывают. `TWITCH_USE_BOT` не меняет аккаунт ответов музыкальных команд: они всегда используют Bot Account.

## Структура

- `src/commands.ts` — команды чата.
- `src/bot.ts` — обработка событий, права, дубликаты и награда.
- `src/music/queue.ts` — последовательная очередь и управление.
- `src/music/youtube.ts` — проверка ссылок и получение аудио через yt-dlp.
- `src/music/mpv.ts` — аудиоплеер и локальные JSON IPC-команды.
- `src/config.ts` — настройки; `src/main.ts` — запуск и остановка.

Перед эфиром проверьте два заказа подряд, `!песня`, паузу, продолжение и пропуск от модератора, а также звук в OBS. Автотесты проверяют очередь и API на подменах; доступность YouTube и реальный аудиовыход нужно проверять на компьютере вещания.

Протоколы: [Streamer.bot WebSocket API](https://docs.streamer.bot/api/websocket/requests), [mpv JSON IPC](https://mpv.io/manual/stable/#json-ipc), [yt-dlp](https://github.com/yt-dlp/yt-dlp).

## Форматирование кода

В проекте используется Prettier: отступы в два пробела, одинарные кавычки, точки с запятой и ширина строки 100 символов.

```sh
npm run format        # Отформатировать проект
npm run format:check  # Проверить форматирование без изменения файлов
npm run check         # Форматирование, TypeScript и тесты
```

Настройки находятся в `.prettierrc.json`, исключения — в `.prettierignore`. C#-файл `streamerbot/Dispatch.cs` не форматируется: стандартный Prettier не поддерживает C#.

## Если бот не отвечает в чат

После подключения консоль отдельно проверяет авторизацию WebSocket и настройки Twitch-аккаунтов. Само сообщение «Подключено к streamer.bot» ещё не означает, что отправка доступна.

1. В **WebSocket Server** включите **Authentication**, задайте пароль и внесите его в `STREAMERBOT_PASSWORD` в `.env` (файл `.env.example` автоматически не загружается). Перезапустите сервер и бот.
2. Подключите **Twitch Broadcaster Account** и **Bot Account** в streamer.bot. Значение `TWITCH_BOT_LOGIN` само по себе не авторизует аккаунт.
3. Проверьте `TWITCH_CHANNEL`: он должен совпадать с каналом подключённого стримера.
4. Отправьте `!песня` с аккаунта зрителя или стримера. Команды от Bot Account игнорируются. `!пауза`, `!продолжить`, `!пропустить` и корректная `!громкость` управляют плеером без текстового ответа.

Если ответ не появился, проверьте ошибку в консоли и состояние Twitch-подключений в streamer.bot. Проверка GetBroadcaster подтверждает настройки аккаунтов, но не гарантирует доставку сообщений в Twitch.

Для диагностики включите `DEBUG_CHAT=true` в `.env`, перезапустите бот и отправьте `!песня`. Лог `[WebSocket] Twitch.ChatMessage` подтверждает получение события; строки `[Chat]` показывают причину пропуска или выполнение команды. Если события нет, проверьте подключение Twitch Chat в streamer.bot и правильность WebSocket-сервера. Режим не выводит пароли или полный текст сообщений.

`!очередь` показывает ожидающие треки без текущего. Названия загружаются в фоне; пока название не получено или при ошибке выводится YouTube-ссылка. Длинный список разбивается на сообщения до 500 символов с интервалом 1,1 секунды; повторные вызовы во время отправки не создают дубликаты списка. Очень длинные названия сокращаются до 150 символов.
